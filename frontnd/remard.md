# 网络协议栈可视化教学平台 - 规划文档

## 1. 项目目标
- 构建一个网络协议栈可视化 + 交互式仿真 + 实时抓包的网络协议栈学习平台
- 直观展示：应用层、传输层、网络层、数据链路层、物理层、网络设备、数据包流向
- 展示网络设备工作原理：路由器、交换机、防火墙、网关等
- 支持功能：
  - 手动配置参数：端口、IP、MTU、窗口大小、映射、延迟、丢包率等
  - 网络故障模拟（网络拥塞、数据包重传、连接超时、路由断开等）
  - 实时抓包和报文分析
  - 当前状态和历史记录可回放

## 2. 技术架构设计

### 2.1 前端技术栈
- 技术选型：React + D3/Canvas + TypeScript
- 功能：
  - 动态协议栈图形显示（分层结构：应用层→传输层→网络层→数据链路层）
  - 数据包流动画（应用层 → 网络层）
  - 双向数据包流动（网络层 → 应用层）
  - 网络设备连接图
  - 左侧"实时日志/抓包窗口"（hex + 十六进制）
  - 数据包详情面板：显示各层协议头、路径、时间戳、状态信息

### 2.2 设备图标和视觉设计（可扩展）
- 路由器/交换机/防火墙等设备图标：使用 SVG 矢量图形，支持缩放和高分辨率显示，示例：`<img src="./icons/router.svg" alt="router" />`
- 推荐使用 Element Plus Icon / Iconify 统一图标风格
  - 推荐 `element-plus` 图标：`el-icon-monitor`, `el-icon-switch-button`, `el-icon-s-platform`, `el-icon-lock`, `el-icon-platform`
  - 设备状态颜色编码：绿色（正常）、红色（故障/延迟高）、黄色（警告）
- 动态状态变化和动画效果
  - 数据包流动、路由器闪烁、连接断开、数据包传输等
  - `currentColor` 和 `fill` 动态绑定当前主题模式
- 设备类型 `iconType` 属性：根据节点状态切换不同图标或颜色主题

### 2.3 协议栈各层实现（核心逻辑）
- 内部协议栈模拟：四层模型
- 协议栈实现（接口）：
  - 应用层：HTTP/TCP shell/DNS 等
  - 传输层：TCP/UDP（端口、窗口大小、重传超时、拥塞控制/慢启动）
  - 网络层：IPv4/IPv6、路由、分片
  - 数据链路层：ARP、MAC、CRC
  - 物理层：比特流传输，支持"信号衰减/丢失"模拟
- 可注入"网络中间人攻击、延迟、丢包率、校验和"等参数
- 支持"手动每层控制/自动传输大小"

### 2.4 抓包模块设计
- 实时抓包模块：捕获经过各层的数据包
- 过滤系统：按协议、IP、端口、关键字过滤 + 时间范围
- 支持：
  - 网络缓存管理 PCB（Packet Capture Buffer）
  - 实时显示协议、IP、端口、关键字
  - 时间轴回放和终端对比
  - 导出 PCAP/JSON/CSV

### 2.5 后端（技术选型）
- 用户认证 / 持久化支持
- 技术选型：Python Flask
- 功能：学习轨迹、实验模板、配置参数、用户数据

### 2.6 数据库设计
- 数据库：MongoDB
- 存储内容：
  - 用户信息（用户名、密码、邮箱等）
  - 实验配置（预设场景、自定义配置）
  - 学习记录（实验历史、抓包数据、学习进度）
  - 实验模板（TCP三次握手、HTTP请求、DNS解析等）

## 3. 功能详细 & MVP

### 3.1 MVP（最小可行版本）
- 基础协议栈可视化：应用层、传输层、网络层、数据链路层
- 支持协议：HTTP over TCP over IPv4 over Ethernet + UDP
- 实时指标：吞吐量/延迟/丢包率/RTT
- 协议详情：TCP窗口、MTU、序列号确认
- 数据包详情：每层字段可展开查看

### 3.2 预设实验场景
- TCP三次握手演示
- HTTP请求响应流程
- DNS解析过程
- ARP地址解析
- UDP数据传输
- 网络故障演示（数据包丢失、延迟、乱序、连接中断）

### 3.3 数据包生成方式
- 手动输入数据包内容
- 选择预设的数据包模板
- 自动生成测试数据包

### 3.4 网络故障模拟
- 数据包丢失
- 网络延迟
- 数据包乱序
- 连接中断

### 3.5 扩展功能
- 扩展协议：UDP、ICMP、BGP、TLS
- 节点扩展：路由策略、负载均衡、路由表
- 安全攻击：ARP欺骗、中间人攻击、拥塞控制算法
- 可扩展性：自定义协议/设备
- 实验模式：实时数据包、自动验证

## 4. 用户流程
1. 登录平台（用户注册/登录）
2. 选择实验模式（预设场景或自定义配置）
3. 配置参数：IP、端口、延迟、丢包率等
4. 选择数据包生成方式（手动输入/模板选择/自动生成）
5. 观察每层数据包处理和协议交互
6. 查看抓包数据和日志
7. 注重细节：校验和/序列号/CRC错误等，并记录
8. 导出数据包和配置

## 5. 关键技术实施路径
- 阶段 1：技术选型 + 原型设计（Figma）
- 阶段 2：前端架构 + 协议模型搭建
- 阶段 3：可视化渲染 + 实时交互

- 阶段 5：性能优化 + 功能扩展

## 6. 项目实施计划

### 6.1 时间表
- 项目周期：3-4个月
- 团队规模：2-3人
- 必须完成：前3个阶段（技术选型+原型设计、前端架构+协议模型搭建、可视化渲染+实时交互）
- 可选完成：后2个阶段（抓包模块+回放功能、性能优化+功能扩展）

### 6.2 阶段详细计划

#### 阶段 1：技术选型 + 原型设计（2-3周）
- 确定技术栈：React + D3/Canvas + TypeScript + Python Flask + MongoDB
- 设计UI/UX原型（Figma）
- 设计数据库Schema
- 设计API接口规范
- 编写项目README和技术文档

#### 阶段 2：前端架构 + 协议模型搭建（4-5周）
- 搭建React项目结构
- 实现协议栈核心模型（应用层、传输层、网络层、数据链路层）
- 实现基础协议（HTTP、TCP、UDP、IPv4、ARP）
- 实现用户认证系统（注册、登录、JWT）
- 搭建后端Flask服务
- 设计MongoDB数据模型
- 编写单元测试

#### 阶段 3：可视化渲染 + 实时交互（4-5周）
- 实现协议栈可视化组件（D3/Canvas）
- 实现数据包流动画
- 实现设备图标和状态显示
- 实现参数配置界面
- 实现预设实验场景
- 实现网络故障模拟
- 编写集成测试

#### 阶段 4：抓包模块 + 回放功能（3-4周）
- 实现实时抓包功能
- 实现数据包过滤系统
- 实现数据包详情展示
- 实现历史记录回放
- 实现数据导出功能（PCAP/JSON/CSV）
- 编写端到端测试

#### 阶段 5：性能优化 + 功能扩展（2-3周）
- 性能优化（渲染性能、数据传输性能）
- 扩展协议支持（ICMP、BGP、TLS）

- 优化用户体验
- 编写用户文档和教程
